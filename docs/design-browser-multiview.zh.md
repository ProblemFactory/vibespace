# 一个会话多个浏览器 / 两个标签页聊天窗口各有浏览器 —— 怎么展示

**日期** 2026-09-26 · **状态** 设计稿，等 owner 确认 §0 · **基线** master 69720f2b（2.369.178）+ lane F（split tabs v2，未合入）· 只读取证，零代码

> Owner 原话："确实 得考虑一个会话里可能有多个并行浏览器，怎么展示的问题，你来设计实现一下吧。另外也得考虑如果两个tabbed窗口每个都打开了各自的浏览器，怎么展示的问题，这个你先思考下设计再和我确认。"

## §0 一句话结论 + 确认单

**结论：** 一个会话不管有几个浏览器，仍然只有**一个**"Agent 浏览器"窗口——顶部那条标签条从"只列命名配置"扩成"列出这个会话的每一个浏览器"（agent 自己的、帮手的、agent 开的 Chrome 应用），点哪个看哪个，想同时看就把某个标签弹成第二个普通窗口；两个聊天窗口合成一组各有浏览器时，用 lane F 的"左右各一条标签"，左边切到哪个聊天，右边自动跟到它的浏览器。不做九宫格，不做新窗口类型，不加拖动逻辑。

请逐条回答（是/否，或 A/B）：

1. 一个会话有多个浏览器时，你看到的还是**一个**浏览器窗口，顶部一条标签条列出它的每个浏览器；点标签切换画面。**不做**同屏九宫格。—— 是/否？
2. 每个标签上写清**谁在开**：`agent` / 帮手的名字 / `你`（你接管时）；新浏览器起来时只在条上**多一个标签**，绝不抢走你正在看的那一格。—— 是/否？
3. 想同时看两个：在标签上右键"在新窗口打开"，第二个就是普通窗口，可以并排、可以拖到别的桌面。—— 是/否？
4. 标签条右端一枚 `4/6` 计数；满了变红；点开**只列你自己会话里闲着的浏览器**，每个一键停掉，绝不列别人的。—— 是/否？
5. 两个聊天窗口合成一组、各开了浏览器：标题栏左半是两个聊天标签、右半是两个浏览器标签；**A** 切左边的聊天，右边自动跟到它的浏览器（反过来点浏览器也把聊天切过去）；**B** 各切各的，只靠标签上的颜色和名字分辨。—— 选 A 还是 B？（我推荐 A）
6. 手机上不变：一次只显示一格，切换器里四个窗口都在。—— 是/否？
7. agent 开的真 Chrome 应用：在标签条里也出现为一个标签，点它 = 打开/聚焦那个应用窗口并排在旁边，**不把**应用画面嵌进浏览器窗口。—— 是/否？
8. 帮手浏览器的名字：能对上帮手任务描述时用描述（"帮手：查价格"），对不上就叫"帮手 1 / 帮手 2"。—— 是/否？

**一个会话今天能握几个浏览器。** 四类，注册表里都有，但只有第一类进"附着集合"：

| 类 | 是什么 | 在哪记 | 今天实时视图看得到吗 |
|---|---|---|---|
| 命名配置的租约 | `vibespace-browser use <label>`，一个会话一个 profile 一份租约，别名 + 默认 | `attachmentsFor` `src/browser-profiles.js:1454-1493`（children **排除**，另列于 `children`） | 看得到；≥2 个时出标签条 |
| 会话自己的临时浏览器 | 第一条页面动词时 keeper 建的受管临时记录，`kind:'none'`，不算附着、没有 handle | `ensureEphemeral` `src/server/browser-keeper.js:634`；`ephemerals()` `:277-287` 带 `child:` 标记 | 只有集合为空时作为兜底目标 |
| 帮手的子浏览器 | `vibespace-browser new-child` 铸 `bk-<父>.N`，租约按前缀归父亲 | `CHILD_KEY_RE` `src/browser-profiles.js:1236`，`childHandleFor` `:1431`；`newChild` `browser-keeper.js:1263-1269`；路由 `src/routes/browser.js:603` | **看不到**（研究 2 S9） |
| 桌面应用里的 Chrome | 人的浏览器，走 xpra 逐窗口；agent 被拒 `browser_is_human` | `src/desktop-apps.js:543-560`；`src/server/window-targets-engine.js:273`；**计入**浏览器上限（`othersNow` `browser-keeper.js:202/292/563`） | 不在浏览器窗口里，是 `desktop-app` 窗口 |

上限 `CONCURRENT_CAP = 6` `src/keeper-limits.js:74`；到顶时 `ceilingVerdict` `src/browser-profiles.js:1322-1345` 拒绝启动并**点名所有持有者（含别人的会话）**——研究 2 S8/S11/S12 抱怨的正是这句。digest 已经带 `cap:{used, cap}`（`browser-keeper.js:301`）。

**实时视图今天显示什么、怎么切。** `streamTargetFor` `src/browser-stream.js:110-133`：点名的附着 > 默认 > 唯一 > 第一个 > 临时浏览器；`profileRef` 只在 `set.attachments` 里找别名/id，**子 handle 落到 `not_attached`**，而且桥接拿的 `envPairs` 永远是父会话自己的（`src/server/browser-stream.js:89,111`）——所以帮手的浏览器按构造看不到。标签条 `src/lib/browser-live-window.js:297-315` 只在 `attachments.length >= 2` 时出现（`:299`），数据来自 `GET /api/browser/session/:id`（`:369-376`）——那个答案里**已经有** `children`（`statusFor` `browser-keeper.js:1197-1209`）和 `ephemeral`，客户端没读。一个会话一个实时视图窗口（`syncId = 'win-blive-' + sessionId`，`:609`）；`openSpec {action:'openBrowserLive', sessionId, profileId}` 可指定看哪个配置（`:100-106, :621-625`）——也就是说"每个浏览器一个窗口"今天已经可以做，只是没有入口。标题 = `<配置> · <会话名>`（`src/browser-stream.js:298-301`）；标签上的归属点来自 `leases`（`ownerDots` `src/lib/chain-layout.js:187-202`）。

**绑定 = 与聊天窗口并排。** "并排到 X 旁" = `bindSplit(聊天窗口, 实时视图, side:'right')`（`browser-live-window.js:285-292`）；自动绑定：digest 里出现一份**新租约**且它的聊天窗口开着 ⇒ 实时视图直接**生在**那条链里（`:597-615`，`createWindow({intoChain})` `src/lib/window.js:70-79,138`）。`bindSplit` 每次都**覆写** `chain.split.pair`（`src/lib/tab-group.js:359-360`）；点第三个标签替换非锚面（D19(a) `chain-layout.js:99-106`）。

**两个 tabbed 聊天窗口今天会怎样。** 链 `[聊A, 聊B]`，B 的浏览器先起 ⇒ pair `[聊B, 览B]`；A 的再起 ⇒ pair 被覆写成 `[聊A, 览A]`，览B 退成隐藏标签；之后点"聊B"标签走 D19(a)：替换掉览A ⇒ 屏幕变成 `聊A | 聊B`，两个浏览器都不见。——这就是 owner 问的那个洞。lane F（commit "split tabs v2"，未合入）把模型改成**每个标签属于一侧**（`split.left/right`，`chain.order`，点标签在它自己那侧显示，≤768 一条条），解决"两侧各自可切"，但**没有**"切了聊天就跟着切浏览器"这条联动。手机：≤768 只显示焦点格（`public/style.css:4748-4753`），研究 2 S10 的空白聊天就是焦点格落在浏览器上。

**尺寸（lane I 审计，`/tmp/vibespace-lanes/audit-i/analysis.txt:290-299`）。** 1400 px 下工具栏自然宽度 zh 995 / ja 1133 / en 1149 px（Watch），接管态再 +140～+210；lane I 之后：URL 最小 120 px，永不折叠的底 71–99 px，其余按优先级折进 `⋯`（`barLayout`，`src/lib/live-bar-layout.js`）。标签条本身**没有**折叠规则：验证者量到 480 px 下两个 40 字标签 267+230 px 直接横向滚动、条高 27→42 px。

## §2 (A) 一个会话多个浏览器

**共同前提。** 列表 = `attachments ∪ {ephemeral} ∪ children ∪ {agent 开的桌面 Chrome}`，一个 PURE 函数 `browserListFor(status)` 从 `GET /api/browser/session/:id` 的现有答案算出来；每项 `{ref, kind: attachment|ephemeral|child|desktop-app, label, state: running|idle|released|ended, driver: agent|<帮手名>|you|<别的会话>, isDefault, owners}`。`driver` 来自 keeper 已有的 `inputs`（`statusFor:1207`）与租约。

**A1 标签条（推荐）** —— 今天的条扩成"每个浏览器一枚标签"：

```
┌ 工作 · VibeSpace 主开发 ──────────────────────────────── ⫿ ─ □ ✕ ┐
│ ● 工作(默认) agent │ ○ 个人 你 │ ◐ 帮手：查价格 │ ○ Chrome 应用 ↗ │ ▾+1 │ 4/6 │
│ agent 正在操作 │ 接管 │ https://portal.example/orders… │ ⋯                      │
│ ┌───────────────────────────────────────────────────────────────────┐ │
│ │                        （JPEG 帧，净缩放 1）                          │ │
```
- 标签 = 状态点 + 名字（≤16 字符省略，CJK 最宽 ≈ 34+176 px，拉丁 ≈ 130 px）+ 谁在开 + 归属点；`↗` 的那种是链接：点它聚焦/打开对应的 `desktop-app` 窗口（§4）。
- 条用 lane I 的 `barLayout` 规则：**正在看的**永不折叠（priority 0），正在跑命令的 1，其余 2，右到左折进 `▾+N`；6 枚标签 ≈ 780–1260 px，所以 600–900 px 宽下必然折叠，这条规则不是可选项。
- 新浏览器出现 = 条上**尾部多一枚标签**（digest 事件），绝不切换正在看的面；接管中尤其不切（换了目标 = 换了 relay，`lease.input` 归属会错）。
- `4/6` 从 `digest.cap` 直读；6/6 变红；点开 = **只列本会话（含帮手）的闲置浏览器** + 每行"停掉"（B-325a 的落点）。第 7 个：keeper 照旧拒绝 agent 的启动（`browser_cap`），条上**不出现**任何"排队中"标签（keeper 明说"nothing of yours is queued"），聊天里的拒绝卡和红色 `6/6` 是同一句话的两个面。
- 状态点：绿脉冲 = 正在跑命令（今天只有当前 relay 知道；其它标签用 digest 每 2 s 合并一次的 `lastVerbAt`，不逐命令广播），灰 = 空闲，空心 = 已释放/已结束（"视图绝不启动浏览器"——研究 2 H 项）。

**A2 网格** —— 一个窗口里 2×2 同屏：

```
│ ┌────────────────┬────────────────┐
│ │ 工作 · agent    │ 个人 · 你       │
│ ├────────────────┼────────────────┤
│ │ 帮手：查价格     │ Chrome 应用 ↗   │
```
D19 已量过三个面在常用宽度不可用；每格再受 320 px 的面底限；N 格 = N 条 JPEG 流每个客户端。

**A3 弹出** —— 每个浏览器一个普通窗口（`openBrowserLive({sessionId, profileId})` 今天就支持，`:100-106`），入口 = 标签右键"在新窗口打开"。窗口多了靠归属色和标题分辨；它和 A1 **不互斥**。

| 点 | 削减 | 成本 | 风险 | 做否 |
|---|---|---|---|---|
| A1 条列出全部四类 | 不做新窗口类型；条的 DOM/CSS 已在（`style.css:4522-4526`） | 低：一个 PURE 列表 + 客户端读 `children/ephemeral` | 低 | **做** |
| A1 折叠 + 16 字省略 + `▾+N` | 复用 `barLayout`，不写第二套 | 低 | 低 | **做** |
| A1 "谁在开"一列 | 只画 keeper 已记的 `inputs`/租约，不新增数据 | 低 | 低 | **做** |
| A1 `4/6` + 只列自己的闲置 | 拒绝文案改窄（不列别人）| 低–中（拒绝句 + 停掉动作走现有 stop） | 低 | **做**（= B-325a 的一半） |
| A1 其它标签的活动脉冲 | 只做 2 s 合并的"最近一次动作"，不逐命令推送 | 中（digest 多一个字段） | 中：digest 抖动 | **先不做**，只给当前标签脉冲 + 其它标签 title 写"最近动作 12 s 前" |
| A2 网格 | — | 高（N 路流、布局、面底限） | 高：D19 实测不可用 | **不做** |
| A3 弹出 | 复用 openSpec | 极低（一条菜单项） | 低 | **做** |

## §3 (B) 两个 tabbed 聊天窗口各有浏览器

三个选项，都建立在 lane F 的"两侧各一条标签"之上（没有它，(B) 在 v1 模型里无解——§1 末段）。

**(a) 一个"跟随当前标签"的实时视图绑在链上**

```
┌ [聊 A][聊 B]        ⫿        [Agent 浏览器（跟随当前聊天）] ─ □ ✕ ┐
```
一个窗口，目标会话随左侧活动标签变。要一种新的 openSpec（`follow:'chain'`）、一种会换会话的视图（接管态、Actions 面、录制指示全按会话重置）、一条"链没了它去哪"的生命周期。

**(b) 各自的实时视图 + 联动（推荐）**

```
┌ [聊 A][聊 B]    ⫿    [A 的浏览器][B 的浏览器] ─ □ ✕ ┐
│  A 的对话              ┃  A 的浏览器 · agent 正在操作     │
```
每个聊天照旧有自己的实时视图（auto-bind 已经是 `side:'right'`，`:611`），链 = 左 `[聊A, 聊B]`、右 `[览A, 览B]`。新增**一条** PURE 规则 `partnerFor(chain, tabId)`：一个标签的伙伴 = 另一侧里 `sessionId` 相同的那枚（聊 ↔ 它的实时视图）；`switchTab` 之后若伙伴在**另一侧**，把那一侧也切到伙伴（对称：点右边的"B 的浏览器"也把左边切到聊 B）。伙伴在同一侧（比如 mergeDropLayout=split 把两个聊天分到了左右）就不动，点谁显示谁。

**(c) 一个实时视图列出两个会话的浏览器，按会话分组**

```
│ A: ● 默认 │ ○ 工作 ‖ B: ● 默认 │ 3/6 │
```
= (a) 的窗口 + §2 的条再加一层会话分组；条更长，接管/录制/Actions 都要按会话隔离。

**四个时刻各看到什么：**

| 时刻 | (a) 跟随视图 | (b) 各自 + 联动 | (c) 分组条 |
|---|---|---|---|
| 切标签 | 右格换会话：画面、模式、URL 全部重连重画（一次可见的空白） | 右格切到伙伴标签：它本来就连着，**零重连** | 条内切组 |
| 并排（⫿）| 只能是"当前聊天 \| 跟随视图" | 左右各选：默认 `聊A \| 览A`；想比较 = 弹出第二个浏览器窗口（§2 A3） | 同 (a) |
| 手机 ≤768 | 一格；切换器里只有"Agent 浏览器"一项，不知道跟的是谁 | 一格；切换器四项，名字各自带会话（lane F R6 一条条） | 一格 |
| 重连 / 刷新 | 视图要先解析"当前标签"再连 | 每个视图各自重连（`:402-405`），链从 layouts 恢复（sides 由 lane F 持久化） | 同 (a) |
| 一个会话结束 | 跟随视图在那个标签上显示"已结束"，切走就恢复 | 它的浏览器标签变空心"已结束"，留在右侧；关掉即走现有 `_detachFromChain`；伙伴规则找不到伙伴就**什么都不切** | 该组标签空心 |
| 双客户端 | 新的同步语义（"跟随"要进同步键） | 联动在**点击的那个客户端**上执行，另一端收到结果（`active` 本来就随窗口状态同步），同步键不变 | 同 (a) |

| 点 | 削减 | 成本 | 风险 | 做否 |
|---|---|---|---|---|
| (b) `partnerFor` + `switchTab` 一处钩子 | 零新窗口类型、零新 openSpec、零持久化字段（伙伴由 sessionId 推导） | 低（PURE 函数 + 一行钩子 + lane F 的 sides） | 低；依赖 lane F 先合入 | **做** |
| (b) 联动的开关（每链一个布尔）| — | 低 | 想"看 A 的聊天配 B 的浏览器"的人今天走弹出 | **不做**（被问到再加，理由：布尔要有用例） |
| (a) 跟随视图 | — | 中–高（新 openSpec、会话切换、生命周期） | 中：接管态跨会话是钱和权限 | **不做** |
| (c) 分组条 | — | 高 | 高（同 (a) + 条更挤） | **不做** |

| 手机空白聊天（研究 2 S10）| 焦点格必须是切换器点名的那格 | 属 lane F R6 / naive #4 | — | lane F 修，本设计不重做 |

## §4 与 E2 / B-325a / B-89d0 的衔接

**E2（agent 开的桌面 Chrome，B-830d，排队中）。** 它是浏览器工具最底层的 rung，默认与 agent 当前窗口并排打开——已经是一个 `desktop-app` 窗口（window-live 形态：agent 芯片、树/像素模式、pin 的 1080p、缩放芯片；审计量到它的工具栏 zh 739 / ja 937 / en 848 px），画面是 xpra 不是 JPEG。所以它在 §2 的条上是一枚**链接标签**（`kind:'desktop-app'`，`↗`）：点它 = 聚焦那个窗口（没开就按 E2 的默认并排打开），**不**把 xpra 客户端嵌进 `browser-live`——两套画面外壳（`picture-shell.js` vs `browser-live`）合一是 E2 之外的另一条 lane，而且 keeper 的 count seam 已经把它算进 `4/6`，条上的计数天然一致。"谁在开"列读 window-live 的租约：agent 持有 = `agent`，你接管 = `你`。

**B-325a（闲置释放）。** 今天临时浏览器只要会话活着就握着租约，`browserIdle`（`src/browser-profiles.js:1307-1313`，`browser.idleTimeoutMs` `settings-schema.js:423`，默认 15 min）永不触发——"做完的会话占位 15 分钟"就是这么来的。B-325a 改成**回合结束几分钟后释放临时浏览器**：条上的标签**不消失**，状态点变空心"已释放（下条命令再起）"，`4/6` 减一；下一条页面动词经 `ensureEphemeral` 重起时标签回到实心。拒绝句改窄：只点名**本会话**的持有者，其它一律"另有 N 个浏览器在别的会话里"；`6/6` 点开的"停掉"只作用于自己的。这两条是 B-325a 的验收，本设计只规定它在条上长什么样。

## §6 实施记录（lane P，2026-09-26）

建了什么，以及与上文不同之处（各附理由）：

- **列表** = `src/browser-stream.js` 的 PURE `browserListFor(status)`，只读 keeper 自己的 status 答案：`attachments ∪ ephemeral ∪ children`（桌面应用那一类等 E2）。行状态：`running`（有命令在跑——只有当前 relay 知道，由客户端传入）、`idle`（进程活着）、`released`（不在跑：回合后释放、空闲退出、被停、从没启动过）、`ended`（失败）。`driver` = `agent` / `helper` / `you`（帮手的**名字**在行的 `helper` 字段里，就是标签上的字）。

### §6.2 收尾验证（lane P verify r2，2026-09-26）

1. **终端会话的浏览器在干活途中被释放**（MAJOR）：释放时钟通过 `turnOf` 读会话的回合，而它读的字段只有**聊天**会话会写——终端模式的 `claude` / `codex` 永远读成"空闲"，于是它的浏览器和帮手们的浏览器在最后一条浏览器命令 3 分钟后被停掉，agent 其实还在干活。现在只有在会发布回合的模式里才回答回合（PURE `turnKnown`：聊天）；其它一律是"未知"，什么都不释放——终端会话的浏览器照旧由 CLI 自己的空闲超时结束（本 lane 之前的行为）。钉在接线上（test-architecture §61），并用接线自己的函数驱动真实 keeper（聊天会话回合结束仍会释放——正向对照）。
2. **视图在启动途中接上了浏览器**（minor）：记录在启动前就是 `starting`，标签条画成空闲，空心视图立刻重连；keeper 随即在 `open` 还没跑完时问了 `stream status`。现在 `streamPortFor` 的三个分支（本会话 / 帮手 / 附着配置）都先等正在进行的启动结束；启动失败就是视图的答案（在一个没起来的浏览器的环境对下跑 `stream status` 会起一个 daemon——等于视图启动了浏览器）。**修的时候在真实 0.38.1 上实测：** 二进制会把这条 `stream status` 排在 `open` 之后执行；验证者看到的 daemon **重启**来自一个空闲超时与 daemon 启动时不同的客户端——而 keeper 用的是设置值，agent 的命令和视图却都跑在会话生成时的环境对下（agent 自己的第一条命令也会这样把 keeper 刚起的浏览器换掉）。所以现在 keeper 用会话环境对里写的空闲超时启动它的浏览器；改过的设置在对话下一次生成（resume）时生效，与其它环境对一致。
