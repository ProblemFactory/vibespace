## 3. Schema-drift design (known types with unknown fields)

**Finding that motivates it:** the live buffers already carry three fields on handled shapes that the 2.1.274 SDK schema does not declare — `system/init.messaging_socket_path`, `system/task_started.owned_by_subagent`, `system/task_progress.workflow_progress` (all three exist as strings in the binary, none is in the zod object; the SDK objects are plain `z.object`, so the CLI emits more than it publishes). VibeSpace silently depends on one of them (`workflow_progress`). Nothing today would notice a fourth.

**Module:** `src/record-shape.js` — PURE, imports nothing, CJS so the bundle carries it.
- `SHAPES[key] = { known:Set, ignored:Map<field, reason>, enums:{field:Set} }`, key = `<harness>:<carrier>:<shape>` — e.g. `claude:stream:system/init`, `claude:transcript:system/api_error`, `codex:rollout:item/McpToolCall`. Carriers are separate because the wire is snake_case (`duration_ms`) and the transcript row is camelCase (`durationMs`) with an envelope — a transcript row is never judged by the stream schema.
- `ENVELOPES`: claude transcript `{parentUuid, logicalParentUuid, isSidechain, isMeta, timestamp, level, userType, entrypoint, cwd, sessionId, version, gitBranch, slug, promptId, requestId, uuid, __line}`; codex rollout `{timestamp, ordinal, type, payload}`; VibeSpace-own wrapper fields `{webui_peer, webui_queue_id, webui_after_commit, webui_origin, webui_origin_note, modelPinned, wrapper, permissionMode, session_name, agent_role, item_id, thread_id, turn_id}` — a declared group "ours", never drift.
- `shapeKeyOf(harness, carrier, record)`, `unknownFields(harness, carrier, record) → {shape, fields:[…], enumDrift:[{field,value}]} | null`. Depth: top level plus the declared nested objects only (`rate_limit_info`, `unifiedWindows`, `compact_metadata`, `usage`, `error`, `item`, `info`, `rate_limits`); `user`/`assistant` are judged by content-block `type` only (`text, thinking, redacted_thinking, tool_use, tool_result, image, document, search_result, fallback`).
- A field is never deleted from `known`, only moved to `ignored` with a reason (old transcripts replay).

**Hook:** in `MessageManager._processMessage` and `CodexMessageManager._processRecord/_processEvent/_processItemCompleted`, after routing: `this._noteShapeDrift(record)`. Per-session `Set` of `shape|field` ⇒ ONE card per shape per session listing the new fields; a second occurrence adds fields to that card (meta op) instead of a new card. Emits `{noticeKind:'unknown-fields', content:[{type:'unknown_fields', harness, shape, fields, enumDrift, sample}]}`; `sample` = `unknownRecordJson(record)` through a redactor that masks values under keys matching `/token|secret|key|authorization|password/i`. Telemetry `harness-shape-drift` once per process per shape (detail = `shape +{a,b}`), same as the record breadcrumb.

**User surface:** a card titled "New fields on a known record: system/init +{messaging_socket_path}" — red border like the Unknown-event card but with the dim variant of the head; "Full record" expander; folds under the existing `unknown` kind of `chat.collapseKinds` (label becomes "N unknown events / new fields"). Diagnostics: the telemetry `byName` list already surfaces the names; add a "Harness drift" block that lists `harness-shape-drift` + `cli-unknown-*` + `codex-unknown-record:*` with first/last seen and CLI version (the buffer's `claude_code_version` / rollout `cli_version`).

**False positives:** (a) `ignored` per shape is a DECISION with a reason, exactly like the record lists; (b) envelope and "ours" groups; (c) carrier split; (d) depth limit; (e) enum drift is informational — the binary itself says "treat an unrecognized kind exactly like a recognized one", so handlers must keep working and only the card fires; (f) fields historically emitted stay known; (g) the workflow journal path and fixture-guard synthetic ids are excluded by rule.

**Tests — `scripts/test-record-shape.mjs` (fast tier, registered in ci.mjs):**
§1 census leg over the tracked fixtures (`scripts/fixtures/**`, never production `~/.claude` — the 2026-09-09 fixture rule): every field on every handled shape ∈ known ∪ ignored ∪ envelope ∪ ours; an optional printed local leg over `~/.claude/projects` + `~/.codex/sessions` behind `VIBESPACE_SHAPE_CENSUS=1` (SKIP with reason in the gate).
§2 synthetic: `system/init +{foo,bar}` → one card naming both, the second record adds no card, telemetry once; codex `token_count.info +{baz}` likewise.
§3 enum leg: `vcs_state_changed kind:"squash"` → enum-drift card, handler still runs.
§4 **binary oracle** (SKIP with reason when no claude binary): the extractor used for this census (walk `u({type:R("…"),subtype:R("…")…})` skipping string literals) reads the installed binary's union and asserts every subtype ∈ HANDLED ∪ KNOWN_IGNORED ∪ `DECLARED_UPSTREAM_UNSEEN` (the list above, each with a one-line disposition), and every shape's binary field set ⊆ known ∪ ignored — red locally on the day the CLI updates, printed in the mirror.
§5 negative control: a scratch copy with `ignored` emptied must go red on §1.
