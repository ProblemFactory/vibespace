## 0. Thesis

Today an agent has **two** doors to the same browser: bare `agent-browser` (landing on "its own" browser through the four `AGENT_BROWSER_*` variables the spawn puts in the session) and `vibespace-browser -- <args>` (lease, typed refusals, audit, the takeover pause). The manual's first sentence is "you browse with the `agent-browser` CLI, the same way you always have". So §3.7's residue never went away: the wrapper is a **subset**, `snapshot`/`fill`/`click` run bare, layer ①'s guarantee covers only the half that went through the wrapper; during a takeover only the wrapper form is stopped by `browser_paused`; only the wrapper form is audited; and nobody watches the ephemeral browser ("Nothing is watching your EPHEMERAL browser" is the manual's own line).

The owner's ruling folds the three into one: **one door**. `vibespace-browser` takes every page verb directly (`vibespace-browser open <url>`, `vibespace-browser click @e3`), the name `agent-browser` is shadowed on every session PATH by a shim that refuses everything, the ephemeral browser is managed by the keeper exactly like a named profile, and an agent is never told `agent-browser` exists. The rename (direction B) gives the user's three faces their own names.

**What does not change:** `browserKey` = the conversation (§3.2.1); named profiles, leases, pins, handles, the attachment set, `profile_changed` (§3.7/§3.8); the live view / takeover / handback (§4.3); the action trace (P5); CDP mediation (P6); providers / backend switch (P4); window targets (P9). Not one id, openSpec, settings key or rail id moves.

## 2. Invariants

* **I1 One door.** The only browser command a session can run is `vibespace-browser <verb>`. `agent-browser` on a session PATH resolves to a shim that refuses and points the way — no forwarding, no compatibility.
* **I2 Every verb rides the lease.** Every page verb passes `/resolve` before it runs: an attachment (or §5's managed ephemeral browser), the one-time `profile_changed`, `browser_paused`, `browser_restarting`, the audit. There is no "outside the wrapper" verb any more.
* **I3 Raw CDP never leaks.** `connect`, `get cdp-url`, `--cdp`, `--auto-connect` are refused by name; a CDP url exists only in the mediator's `ws://127.0.0.1:<p>/m/<token>/…` form, handed by the server to a child we exec ourselves, never printed. **r4:** measured, the binary launches every browser with `--remote-debugging-port=0`, so a random raw port always exists; against an agent running as the same user, I3 is exactly "the sanctioned road never prints it" (§3.3 r4, §9) — not "no raw port listens".
* **I4 The ephemeral browser is watched.** A conversation's first browse gets a keeper record: start, idle, runaway, ceiling, live view, takeover, trace, restart adoption, sweep — exactly like a named profile. The manual's "nothing is watching" sentence disappears.
* **I5 An agent never hears of `agent-browser`.** The teaching lines, the hook's intro, the manual, the skill text, the `vibespace-window` line, every refusal sentence: zero mentions (test-architecture's new census §52 greps the teaching functions in `src/agent-routes.js`, `docs/agent/*.md` and the string literals of `data/bin/vibespace-*`; **r2:** of EVERY tracked `data/bin/vibespace-*` — r1 scanned only the two browser CLIs — plus the route/engine modules whose refusals reach the agent, window-targets and browser-trace included, and the agentd bundle, whose only hits must be `floorNotice`'s user notice; **r3:** the route/engine scope is a GLOB — every `src/routes/*.js` and every `src/server/{browser,window}-*.js`, so a new module is scanned by existing — and each user-only exception is one FUNCTION wide: `floorNotice`, and browser-env's operator `journal`). The only exceptions: the shim's own line (it must name what it shadows to point the way), `floorNotice` (a server notice to the USER) and the kb/design docs.
* **I6 A human's window is not an agent's.** A browser launched from Desktop apps is refused by name `browser_is_human` on `open` **and** on `attach`; `list` omits it.

## 3. T1 — one CLI: `vibespace-browser` takes every page verb directly

### 3.1 The verb model (PURE `src/browser-verbs.js`, shared by the CLI and the bundle)

`classify(argv, {ours})` → `{kind, verb, sub, argv, code?, error?, remedy?}`, `kind ∈ ours | page | refused | escape`. Order: ① strip `--profile <h>` (ours, anywhere) ② the first non-flag word ③ in the OURS set ⇒ `ours` ④ `--` ⇒ `escape` (the argv after it is judged by ⑤⑥ all the same) ⑤ the flag rules (§3.3) ⑥ the verb table (§3.2). **`batch`**: every line (stdin or args) is classified on its own; one refused line refuses the whole batch before anything runs, naming the line.

### 3.2 The verb table — verb → mediated path → refusal codes

**VibeSpace's own verbs (OURS, 12, they always win):** `profiles new providers use detach status pin watch backend blocked new-child help`.

**The complete collision list:** of agent-browser's ~70 top-level words exactly **one** collides with OURS: `profiles` (agent-browser: list Chrome's user profile names; VibeSpace: the registry). Resolution: VibeSpace wins; agent-browser's is reachable as `vibespace-browser -- profiles` (it lists names only — harmless). One flag collision: `--profile` (agent-browser: a Chrome profile name or a **directory path**; VibeSpace: a handle) — VibeSpace eats it, a path form is refused `profile_path_refused` as today (§3.7), after `--` too. `session`/`status`/`new`/`use`/`pin`/`watch`/`backend`/`blocked`/`detach`/`providers`/`new-child` are not agent-browser top-level words (`session` is, but does not collide with OURS — it is refused, see the table).

**r1 addendum (two reproduced gaps).** ① **Flag position:** 0.32.0 reads global flags ANYWHERE in the argv — `get --json cdp-url`, `get -c cdp-url` and `get cdp-url --json` all answer the raw endpoint — so a verb's noun is the first NON-flag word after it (value flags skip their value, `nounAt`), and any non-flag word of a `get` that is `cdp-url` is `raw_cdp_refused`; batch lines and the `--` form likewise. ② **Env twins:** every refused flag has an environment twin the real binary honours (`AGENT_BROWSER_CDP / _AUTO_CONNECT / _PROXY / _ARGS / _EXECUTABLE_PATH / _HEADED / _STATE / _PROFILE / _SESSION / _CONFIG / _RESTORE_*` …, from the binary's own table). D1's "the four pairs kept" covers the pairs VibeSpace SETS, not the ones the agent adds; so the child env is BUILT: EVERY `AGENT_BROWSER_*` key of the shell dropped, then the output-only keys (`JSON / DEBUG / MAX_OUTPUT / …`) and the socket root, then the session's own spawn pairs as the server recorded them (`/resolve`'s `spawnEnv` = `_browserEnv`; on rung H `hostProfile` names the scratch dir the host exported for this conversation), then `/resolve`'s pairs verbatim and its `unset`. A dropped key the agent added is said once on stderr by name (`[env_twin_dropped]`, never its value). An older server's answer (no `spawnEnv`) keeps the identity pairs as the shell has them; every other twin still goes.

**r2 addendum (two more reproduced gaps, and one the fix itself exposed).** ① **The noun decides, never a later word.** r1's "any non-flag word of a `get` that is `cdp-url`" refused legitimate reads: `get attr @e cdp-url` reads an attribute NAMED cdp-url and `get text cdp-url` an element of that name (measured on 0.32.0: `zzz` and the element's text, no endpoint). Only `sub === 'cdp-url'` refuses now — and that is sound only if `nounAt` skips exactly what the binary skips: every GLOBAL value flag (the `Authentication:` + `Options:` sections of `--help`; test-browser-verbs derives them from the checked-in census and fails on one missing from `VALUE_FLAGS`, or on a boolean one in it) and — measured while checking the proposed fix — the optional `true`/`false` a BOOLEAN global flag takes ("Boolean flags accept an optional true/false value": `get --json true cdp-url` IS the raw endpoint, `get --json TRUE cdp-url` is `Unknown subcommand`). `flagEnd` models both; a non-global flag between the verb and its noun is the binary's `Unknown subcommand` (so skipping it can only over-refuse). r1's claim that `get -c cdp-url` answered is wrong (`-c` is a snapshot option; `Unknown subcommand`). test-browser-mediation-chrome ③ runs every spelling through the real binary and holds the router to its answer. ② **The socket root is identity, not output.** The daemon a command talks to is `<root>/namespaces/<ns>/run/<session>.sock`, root = `AGENT_BROWSER_SOCKET_DIR` > `$XDG_RUNTIME_DIR/agent-browser` > `$HOME/.agent-browser`; r1 kept the shell's SOCKET_DIR (an "output" key) and XDG_RUNTIME_DIR, so `export AGENT_BROWSER_SOCKET_DIR=/tmp/mine; vibespace-browser open …` drove a daemon the keeper never launched, streams, traces, idle-guards or counts (I4) — or one the agent pre-started there with any flag. SOCKET_DIR leaves `ENV_PASS`; a LOCAL session's `/resolve` answer names the root the keeper's own runtime uses for that browser (`socketDir` — `keeper.socketRootOf(pairs)`: the runtime's base env + the pairs naming the browser; an attachment's never carry SOCKET_DIR, an ephemeral's may) and the runtime dir it runs with (`runtimeDir`, null = none), and the CLI sets both on the child LAST (no pair or `unset` moves them); a replaced value is named in the `[env_twin_dropped]` note. Rung H (unmanaged, D8) names only the base of the short directory its prelude exports on a long home (`hostSocketBase`): a shell value is kept only when it is exactly `<base>/vs-ab-<this uid>`; XDG_RUNTIME_DIR there stays the host shell's (the prelude decided on it; no keeper to be blind). Cross-conversation isolation was never at stake (the namespace is server-forced); the gap was the keeper's view of a conversation's OWN browser through the sanctioned road.

**r3 addendum (one major and one medium reproduced gap).** ① **The flag table is a measurement, not the help.** `get --idle-timeout 5m cdp-url` printed the raw endpoint: `--idle-timeout` is a GLOBAL value flag the binary strips anywhere, and the `--help` documents it only in its `Environment:` section (as `AGENT_BROWSER_IDLE_TIMEOUT_MS`), so the r2 census over the `Authentication:` + `Options:` sections never saw it and `flagEnd` took `5m` for the noun. The router's `VALUE_FLAGS` / `BOOL_FLAGS` are now MEASURED (`scripts/browser-flag-census.mjs`: every flag-shaped string in the binary's bytes run launch-free as `<flag> zzq9 session list` — the session list answering ⇒ a value flag, `Unknown command: zzq9` ⇒ a boolean, `Unknown command: <flag>` ⇒ not global; 792 strings, 35 value, 19 boolean on 0.32.0, the fixture `scripts/fixtures/browser-verbs/global-flags-0.32.0.json`; the fast gate holds the tables EQUAL to it and the heavy gate re-measures the installed binary). Defence in depth, because a future build can add a flag before its table does: `get` passes only with a noun it READS (the closed `GET_NOUNS`, the help's `Get Info` row minus `cdp-url` — an allow-list, never a blocklist), and a flag of UNKNOWN arity is judged under both readings (as a boolean and as taking the next word): if either reading reaches `raw_cdp_refused`, a refused verb or a refused flag, the command is refused and the sentence says which reading; a reading the binary would itself reject (an unknown verb/noun) refuses nothing. `get attr @e cdp-url` stays a read. `--idle-timeout` also joins the launch flags (the daemon's lifetime is the keeper's, like its env twin). ② **The config FILE is the last twin — it is named, never searched.** With no `AGENT_BROWSER_CONFIG` the binary searches `~/.agent-browser/config.json` then `./agent-browser.json` in the directory the command runs from (config < env < flags), and the launch keys ride EVERY command — measured: a later `get title` from a directory holding `{"args":"--remote-debugging-port=41777"}` relaunched the running browser with the port open; the verifier's rung-D run layered a session directory's `args` into the generated config and curled the raw port. Now: the keeper runs every browser with a NAMED file (the browser's own generated config, else its `data/browser-env/machine.json` for a profile browser / `machine-ephemeral.json` for an ephemeral one without one — `configFileFor`, one wrapper around every runtime call), `/resolve` names that same file (`config`) and the CLI sets it on the child last; where none is named (rung H, an older server, a keeper that could not write) the CLI composes one by the same rule into `~/.vibespace/browser-config/<content hash>.json` (0600, a 0700 directory it owns) and names it — or refuses `config_unavailable` (a file that does not parse, the binary would refuse too). THE RULE (`sanctionedConfig`, in the verb table so a host's CLI composes by the same words): the user file is the machine's own configuration and is carried — its `args`, proxy, executable, extensions, fence — minus `cdp` / `autoConnect` and minus every `--remote-debugging-*` / `--remote-allow-origins` / `--user-data-dir` / `--profile-directory` switch in `args`; the PROJECT file lives where the agent works, so it only NARROWS: exactly `allowedDomains`, `actionPolicy`, `confirmActions`, `confirmInteractive`, `contentBoundaries`, `maxOutput`, and only where the user file sets none — the binary's own rule would let a project `allowedDomains: ["*"]` REPLACE the owner's fence (the v2 r3 "layer it the way the CLI does" carried its launch keys — that half is withdrawn; the fence half stays). A dropped key is said (the server's journal; the CLI's `[config_keys_dropped]` stderr line). Deliberately NOT stripped: the user file's own launch keys — a machine's `args` legitimately carry `--no-sandbox` or an ozone-platform switch its display needs, and a single-uid agent editing that file is the trust level §9 already names, not an accident. ③ rung H keeps the prelude's short socket dir only when `lstat` says it is a real directory this uid owns (the prelude's own `[ ! -L ] && [ -O ]`).

**r4 addendum (one major, two medium, three low, one informational — each reproduced first).** ① **A navigation goes to the web.** The r3 rule strips a FIXED debugging port from a config's `args`, but the binary launches EVERY browser with `--remote-debugging-port=0` (measured with a dump executable: every launch, whatever the config) and a user-data-dir under `$TMPDIR/agent-browser-chrome-<uuid>`, and two sanctioned page verbs read it back: `open chrome://version` prints the command line and the profile directory, `open file://<that dir>/DevToolsActivePort` the port and the browser GUID — together exactly `get cdp-url`'s answer (test-browser-mediation-chrome ③ r4 runs both bare as the control). Measured on 0.32.0's `open` (`get url` after each spelling): `FILE:` is lower-cased, `file:/x` and `file:x` become `file:///x`, `about:version` navigates, `chrome-extension://` is passed through, and a scheme-less word — `localhost:3000`, `example.com`, even `mailto:x@y` / `myhost:abc` — is made `https://…`; `goto` / `navigate` are the binary's own aliases of `open`. So `localSchemeOf` (PURE, the verb table): after dropping leading blanks and every tab / CR / LF (the URL parser drops them), a word with no scheme passes; `http:` / `https:` / `data:` and `about:blank` (with `/`, `?` or `#` after it) pass; the browser's own and this machine's schemes (`file`, `about`, `javascript`, `blob`, `filesystem`, `view-source`, `devtools`, `chrome` and every `chrome-*`, `edge`, `brave`, `opera`, `vivaldi`, `isolated-app`) are refused `local_scheme_refused` in any spelling, and so is an authority-form `x://…` of any other scheme (only http(s) pages are the web in that form). It judges every positional word after a NAVIGATING verb (`open` / `goto` / `navigate`, `tab`, `window`, `pushstate`, `diff`, `read`, `vitals`, `record`), every word after an escape's unknown verb, and every batch line. Measured this round and closed with it: `state load <file>` navigates the page to every origin its file lists (a crafted file left the page ON `chrome://version`); the judge names the file(s) (`stateFiles`) and the CLI reads each relative to the cwd, as the binary does, and refuses a local origin anywhere in it (`stateFileVerdict`). **What this does not do, said plainly:** a same-uid agent's own shell can read the port off `ss -ltnp`, `/proc`, or that `DevToolsActivePort` file, and a URL on that port (`http://127.0.0.1:<port>/json/version`) then prints the endpoint through any page verb — §9's trust level; the rule restores only "the sanctioned road never prints it", which is all I3 ever was against a same-uid agent. A renderer-initiated navigation (`eval "location.href='file://…'"`) from a web page is refused by the browser itself (measured; the heavy leg pins it), so `eval` does not reopen the road once `open` is closed. ② **The configuration is the ACCOUNT's.** Where an answer names no config (rung H by design; a local keeper that could not write its file), the CLI composed "this machine's own configuration" from `path.join(os.homedir(), …)` — and `os.homedir()` reads `$HOME` first: `HOME=/tmp/mine vibespace-browser open …` made an agent-written `config.json` (executablePath, args, extensions, init scripts) the user file (measured: the composed file named the agent's dump executable, which ran). The user file, the `~/.vibespace/browser-config` directory, rung H's host profile path and the shim directory now come from the passwd entry (`os.userInfo().homedir` → getpwuid; `os.homedir()` only when there is no entry); a `$HOME` that disagrees (realpaths compared) is refused `config_unavailable` naming both, before any file is read or written. sshd sets `HOME` from the same entry, so a legitimate session never hits it. ③ **The stdin batch is the binary's form.** The binary reads a `batch` with no line arguments ONLY as a JSON array of string arrays (plain lines: `Invalid JSON input … Expected an array of string arrays`; `[["get url"]]` is one word); r3 judged stdin as shell lines, so the binary's own form was refused (`batch line 1 ("[[…]]")`) and the plain form was the binary's error. `parseBatchStdin`: text starting with `[` must be exactly that JSON (else `batch_stdin_refused`), each element judged as argv words, the text handed over verbatim; plain lines (blank / `#` skipped) are split like a shell and handed over as the JSON of exactly the words judged. ④ `AGENT_BROWSER_CONFIG` left `ENV_LEGACY_KEEP`: an answer with neither spawn pairs nor a config composes one (the r3 rule: the config is never the shell's). ⑤ `scripts/browser-flag-census.mjs [<binary>] [--write <f>]` takes the positional in either order and resolves a bare name on PATH past the shim. ⑥ **The flag table is trusted only where it was measured.** `TABLE_VERSION` = the fixture's version; the CLI reads the version off the binary it is about to run (`--version` prints and exits: launch-free, ~2 ms measured) BEFORE `/resolve`, and on any other build (or an unreadable one) re-judges the command with every flag of unknown arity (`classify(…, {drift})`) and says `[flag_table_drift]` once — a flag whose ARITY changed between builds can no longer move the noun unseen. (The verifier proposed carrying the keeper's cached version in the `/resolve` answer; that names the SERVER's binary on the server's PATH, cached for 10 minutes, and would be read only after `/resolve` has started a browser — the binary the CLI runs is asked instead.) ⑦ The keeper names its own `machine*.json` only while `lstat` says it is a regular file of this uid with the content it wrote; anything else (a symlink swapped in, an edit) is re-written — the atomic rename replaces the link itself.

## 5. T3 — the managed ephemeral browser

### 5.1 The record

A conversation's (`browserKey`) first page verb with no attachment turns `/resolve`'s `none` branch into `keeper.ensureEphemeral({browserKey, sessionId, envPairs: session._browserEnv, variant})`:

```
profile record  { id: 'bp-<8 hex>', ephemeral: true, label: '(ephemeral) <session name>', owner: {kind:'conversation', id: browserKey},
                  provider: 'chromium', dir: <rung C's scratch dir | null (rung D/N: the CLI's own temp dir)>, sharing: 'owner', createdAt }
browser record  { profileId, ns: 'vs-<browserKey>'   ← the identity is unchanged: P0's SESSION/NAMESPACE are it
                  pid/starttime (`session info --json`), state, startedBy: 'first verb', envPairs }
lease           { profileId, browserKey, alias: 'ephemeral', since }   ← one per conversation; not counted in the handle set (a bare command still lands on it)
```

`nsOf(profileId)` answers `vs-<browserKey>` for an `ephemeral:true` record; `start()` runs `rt.launch(null, {extraEnv: envPairs, idleMs: setting})` for it (the same pairs `streamPortFor`'s ephemeral branch uses — the r3 lesson: **never** re-run the ladder).

### 5.2 The lifecycle

| Event | Behaviour |
|---|---|
| First page verb | ceiling check (§5.3) → runaway-park check → start (or adopt a daemon an escaped command already started: `session info` with a pid ⇒ adopted) → lease → the command runs |
| Idle | the CLI's own `AGENT_BROWSER_IDLE_TIMEOUT_MS` (setting `browser.idleTimeoutMs`, default 15 min) still stops the daemon; the keeper's tick sees the pid gone ⇒ record `stopped` (not an error); the next verb starts it again. The lease does not drop on idle |
| Runaway | exactly as a named profile: sampling, 1 h park, server notice, telemetry |
| Terminate / session death / conversation carried by no live session | `reconcile` drops the lease ⇒ `stop(why:'conversation gone')` ⇒ **`removeProfile` runs by itself** (removing an ephemeral record is not a human's act — it has no name and no reference beyond its owner) ⇒ a rung-C directory is swept by `browser-env.sweep` as today |
| Resume | the same `browserKey` ⇒ the same record (adopted if the daemon still lives) |
| Fork | a new key ⇒ a new record, never inherited |
| Sub-agent (`new-child`) | the child key's own ephemeral record, reaped with the parent (the `reg.children` rule) |
| Server restart | `adoptAll` asks `session info` under the `envPairs` of every `ephemeral:true` record: alive ⇒ adopted; gone ⇒ `stopped` |
| The user pins a named profile | as today: the next verb lands on the pin (`profile_changed` once); the ephemeral record stays until idle + conversation end |

### 5.3 What applies with it, and what it costs

* **Live view / takeover / handback / confirmations / trace / housekeeping:** the parts already keyed on `ephemeral` are untouched; the housekeeping panel gains an "Ephemeral browsers" section (record + whose conversation + state + Stop); `vibespace-browser profiles` does not list them (they are not attachable), `status` does.
* **The ceiling:** ephemeral records **count** against `CONCURRENT_CAP = 6` (D2, default). The seventh session's first page verb gets:
  `browser_cap — 6 browsers are running on this instance (the ceiling shared with desktop apps): Shopping (session A), (ephemeral) session B, …; yours starts when one idles out (15 min without a command) or is stopped by the user (Agent browser panel). `vibespace-browser status` shows the holders; nothing of yours is queued.`
  Honest with the owner: every browsing session is one Chromium (measured ≈ 1.4 GB RSS / 13 processes, parent design §1.2), six of them 8 GB; no different from today — the difference is that today **nobody counts**.
* **Honest limits:**
  * Remote sessions (ssh / paired devices, rung H): the shim shadows there too; `vibespace-browser <verb>` locates the real binary on that machine and runs it under the H-rung pairs — **not managed** (the keeper is local; managing remote ephemerals through the `browser-serve` op is a follow-up, D8). The manual says so.
  * An instance with `browser.isolateSessions` off: no pairs; `vibespace-browser <verb>` runs on the machine's shared browser, audited, unmanaged, `close --all` refused (`shared_browser`); the teaching line says so (D7).
  * The managed ephemeral browser is `sharing:'owner'` and not CDP-mediated (it has one conversation); during a takeover its page verbs are stopped by `/resolve`'s `browser_paused` (I2), not by the CDP judge.

## 9. Security notes

* The shim is **a fact about the PATH**, not a boundary (single uid, parent design §6.5). The boundaries stay: the mediating proxy (shared profiles), the lease + typed refusals (between one owner's sessions), the keeper's supervision. What this design removes are **accidents**: a taught bare door, a CDP url lying in a transcript, a Chromium nobody watches.
* **r4 — the raw port exists, and the road does not print it.** Every browser the binary launches listens on a random `--remote-debugging-port=0` (measured). The agent's shell runs as the same user: it can read the port off `ss -ltnp`, `/proc/<chrome>/cmdline` + the profile directory's `DevToolsActivePort`, or run the real binary by its path — and a URL on that port (`http://127.0.0.1:<port>/json/version`) then prints the endpoint through any page verb, as can a page fed a local file by `upload`. None of that is the sanctioned road, and closing it is not in a single-uid design's reach; what the router guarantees is that `vibespace-browser` never PRINTS the endpoint by any spelling it accepts — `get cdp-url` / `connect` refused, the browser's own pages and this machine's files refused as navigation targets (`local_scheme_refused`), a `state load` of such an origin refused, the config the account's own. Likewise a `node --require …` preload or a copy of the CLI is the agent running its own program, not the CLI.
* Secrets never in argv: `auth *` is refused; `fill @ref "<password>"` is the agent's own act and the audit records the verb only; the output of `cookies get` / `state save` is a secret — the manual's rule stands.
* `agentEnv()` keeps stripping the server-inherited `AGENT_BROWSER_*`; the four pairs a session gets are VibeSpace's own decision.
* Remote hosts: the shim lands in `~/.vibespace/bin` with `AGENT_TOOLS`; with the prelude order fixed it is first on the PATH; `vibespace-browser` on that machine locates the real binary by skipping the shim directories.
